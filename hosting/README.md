# Static hosting

Publish the contents of `release/`, generated by `npm run export`. This folder
contains the engine, launcher, open fonts, licenses and a downloadable snapshot
of the modified source and dependency sources. It contains **no game archives**.
Export checks both this and the 25 MiB per-file Cloudflare Pages limit.

## Download package → local import (default)

The workflow follows [GTA Vice City WASM](https://github.com/joncodeofficial/gta-vice-city-wasm):
**download a tar.gz to disk → select it in the launcher → extract once into OPFS → Play**.
This implementation streams gzip/TAR in a dedicated worker instead of buffering
several GiB in JavaScript memory. The browser verifies the TAR manifest, paths,
sizes, gzip CRC and BIG indexes before marking the installation ready.

```sh
npm run pack:archive
npm run export
npm run preview
# http://localhost:8095
```

The packer uses the already validated `.local/staged` installation. Its output is
`.local/downloads/generals-zero-hour-v1.tar.gz` plus a SHA-256 sidecar. For this
installation: 2,109,815,100 compressed bytes, 2,932,330,249 unpacked bytes,
282 files. The prepared USTAR package begins with `generals-manifest.json`;
arbitrary game archives, installers, ZIP files and ISO images are not accepted.

Upload the tar.gz to the **candc-web** R2 bucket. It stays outside `release/`.
For this large object use S3 multipart upload (the dashboard accepts up to 300 MB):

```sh
aws --profile YOUR_R2_PROFILE \
  --endpoint-url https://6302c36f0df82a59b91be25c025417af.r2.cloudflarestorage.com \
  s3 cp .local/downloads/generals-zero-hour-v1.tar.gz \
  s3://candc-web/generals-zero-hour-v1.tar.gz \
  --content-type application/gzip \
  --content-disposition 'attachment; filename="generals-zero-hour-v1.tar.gz"' \
  --cache-control 'public, max-age=31536000, immutable'
```

Do **not** set `Content-Encoding: gzip`: the downloaded file must remain compressed.
Use a new filename for each edition/update. The attachment header makes the
browser save the file rather than navigate to it. Configure the download URL in
`engine/web/shell/launcher-config.json` before `npm run export`:

```json
{
  "downloadUrl": "https://pub-61901a641aab490598b29fa4887b4d72.r2.dev/generals-zero-hour-v1.tar.gz",
  "label": "Generals + Zero Hour · 2.11 GB · tar.gz"
}
```

A normal download link does not fetch through JavaScript and needs no CORS policy.
The launcher does not need R2 credentials. A private bucket needs a separately
issued download URL; an expiring signed URL must be refreshed. Do not commit
credentials or embed permanent access keys in the static configuration.

Import reads the selected file locally; it does not upload it back to Pages.
Allow roughly 3 GiB of additional disk space for OPFS, on top of the downloaded
archive. You can remove the downloaded file after successful import, or keep it
for another browser/device. Imports can be cancelled and retried by selecting
the same archive again; they restart from the beginning. Partial installations
cannot launch. Save data under `userdata/` is never touched by archive import.
Close other game tabs on the same origin before installing or replacing files.

The public launcher intentionally exposes only archive download, local import and Play.
The underlying folder importer remains available for developer builds.

## Cloudflare Pages (recommended)

Project: `candc-web`. Launcher: https://generals.prosolupov.com/.
Cloudflare Access protects the custom domain, `candc-web.pages.dev`, and
`*.candc-web.pages.dev`, including old deployment URLs. The reusable `generals`
policy allows only the three owner-specified exact email addresses. Unmatched
users are denied; there is no bypass policy. Application sessions last 24 hours.

Bucket download: https://pub-61901a641aab490598b29fa4887b4d72.r2.dev/generals-zero-hour-v1.tar.gz

Public R2 access was explicitly approved by the owner for this bucket. The
`r2.dev` address is suitable for initial testing; configure a custom domain
for production traffic ([R2 public buckets](https://developers.cloudflare.com/r2/buckets/public-buckets/)).


Create a Pages project using **Direct Upload**, and upload the `release/`
folder. Independent single-player sessions need no game server. Our hosted
deployment additionally uses a Pages Function for private diagnostics; deploy
from the repository root so Wrangler includes `functions/` and the R2 binding. Keep the included `_headers` file: it
provides COOP/COEP isolation needed by the WebAssembly threads. Use HTTPS and
prefer a stable custom domain so saves remain under the same origin.

[Direct Upload](https://developers.cloudflare.com/pages/get-started/direct-upload/)
[Limits](https://developers.cloudflare.com/pages/platform/limits/)

The engine is about 8.8 MiB after stripping debug sections. Source archives
are split into 20 MiB parts, downloaded only when someone opens Modified source.
Every file stays below the 25 MiB Pages limit. Publish all source parts and the
manifest along with the program. The normal game launch does not fetch them.

## GitHub Pages

Put the **contents** of `release/` at the root of a dedicated deployment
repository/branch (or in its `docs/` directory), including `.nojekyll`. Enable
Settings → Pages → Deploy from a branch and select that location. Preserve
`source/`, licenses and the service worker. Relative URLs also support a
`https://account.github.io/repository/` subdirectory.

GitHub Pages does not apply `_headers`. The included `coi-serviceworker.js`
adds isolation headers and reloads the page once on the first visit. HTTPS and
service workers must be allowed. Test the deployed URL in a fresh profile.
The published site limit is 1 GB; this asset-free release is about 92 MiB.

[Pages limits](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits)

## Own server

Serve `release/` over HTTPS. `nginx.conf` is a server-block fragment with the
necessary headers and MIME guidance. Do not expose the development workspace,
Downloads, `.local`, or `engine/web/dist` as the public root. No Node/Python
process is needed in production; the local Python server is for preview only.

## Asset delivery choices

| Mode | First visit | Subsequent visits | Host storage |
| --- | --- | --- | --- |
| Downloaded tar.gz (default) | Download to disk, select archive, stream-extract to OPFS | Read OPFS; no game-data transfer | R2 bucket |
| Local folder (alternative) | Select owned installation; stream-copy ~2.73 GiB to OPFS | Read OPFS; no game-data transfer | None |
| Hosted GAXD pack (optional) | Stream-download ~1.85 GiB and decompress into OPFS | Read OPFS; no game-data transfer | Separate large-file store |

Local imports use bounded chunks, not a multi-GB JavaScript ArrayBuffer. They
must finish before play. An interrupted folder import can be retried by choosing
the same folder; it recopies the data. The downloaded pack mode has the upstream
segment resume journal when the server supplies stable ETag and Range responses.
Neither mode is on-demand HTTP streaming of individual game reads. The engine
needs its filesystem installed first. The launcher/engine still need the site
on a new page load; this is not an offline PWA.

To enable **your own** optional asset service, edit `release/assets/builds.json`
after export (export resets it to `[]`):

```json
[
  {
    "name": "owned-disc-v1",
    "label": "Download installation from my server",
    "url": "https://assets.example.com/generals/owned-disc-v1/build.data"
  }
]
```

Create the pack with `npm run assets`; it is at
`engine/web/dist/assets/default_ru/build.data`. Never add it to the public
release by accident. Use only a distribution arrangement you are entitled to
provide. A local folder import lets each visitor supply their own copy.

Large packs exceed both Cloudflare Pages' per-file limit and GitHub Pages'
site-size limit. Use an appropriate separate file server/object store if
choosing download mode. Cross-origin hosting needs GET/HEAD/Range CORS access,
`Access-Control-Allow-Origin` for the app origin, and exposed
`Content-Length, Content-Range, ETag, Accept-Ranges`. Keep URLs stable per pack
version; return byte ranges without transparent recompression. Test any access
control arrangement; the current loader does not send cross-origin cookies.
A developer UI is needed to expose alternate build selection; the public UI uses local import.

Only one installation should be used per browser origin. Separate editions/mods
should use different origins or browser profiles; do not mix archive sets.

## Saves and friends

Save/load inside the game writes to OPFS. Saves remain after page reload and
are private to that browser profile and exact origin (scheme + host + port).
They are not uploaded or synchronized. Avoid private/incognito mode. The launcher
requests persistent storage, but the browser can deny it; keep exports.

Before changing domain, browser or port, open `/saves.html` on the old origin
and choose **Скачать сохранения**. On the destination open `/saves.html`,
choose **Восстановить сохранения**, select
the JSON backup and confirm replacement, then Play. This includes saves, options,
campaign progress and replays under `userdata/`. Export limit is 128 MiB of user
data. Restore validates paths before writing and never targets game archives.
Close other tabs of the game on that origin before import/export to avoid open
filesystem handles. No destructive storage controls are shown in the public launcher.

Your friend can open the same launcher link, download/select the package once and play
campaign/skirmish independently. A shared match is a separate case: upstream
contains experimental WebRTC/MQTT multiplayer and public signaling defaults in
`ice.json`. This release does not claim multiplayer verification or provide a
managed matchmaking/TURN service. Single-player hosting needs neither.


## Session diagnostics (16 October 2026)

The deployed launcher collects bounded diagnostics during gameplay and uploads
chunks every 30 seconds to `/api/diagnostics` on the same origin. Engine and
browser snapshots are taken every five seconds. Ctrl+Shift+F8 sends an immediate
report and displays a Russian confirmation with its UUID **after R2 acknowledges
the write**. This shortcut runs in the browser capture phase, independently of
SDL/game UI input. It cannot work if the entire browser main thread is frozen;
automatically uploaded earlier chunks remain available.

Data includes engine build, browser/device capabilities, map, simulation/client
frames, focus, fullscreen, pointer lock, GUI capture/grab/focus window IDs, input
enabled/paused flags, mouse button states, SDL event counters and dropped input,
heap size, browser frame gaps/long tasks, and bounded console/error messages.
Key values, text input, cookies, tokens, save files and game assets are not
collected. Error strings are truncated and common secrets/URL queries redacted.
Known per-frame engine spam is sampled and excess messages are counted.

Each chunk is at most 48 KiB. The rolling history is bounded to 256 events /
36 KiB, and the retry queue to 16 chunks. Chunks overlap; use event timestamps
to reconstruct the timeline. Retries preserve chunk IDs. Failed uploads back
off up to five minutes. Pending chunks persist in localStorage when available
and retry after reload. Page exit saves a final chunk locally; delivery at page
exit is not guaranteed. Static hosts other than our Pages/custom domain collect
locally but do not auto-upload. Local Pages development uses port 8788.

Storage: private R2 bucket `candc-web-diagnostics`, automatic expiration after
14 days. No public URL. The endpoint validates Cloudflare Access JWT signatures,
issuer and the existing application's audience, then checks the three permitted
players. Reads are restricted to the owner's email. It rejects foreign origins,
malformed chunks and payloads above 64 KiB. Existing Access policies are unchanged.

Read diagnostics while signed in as the owner:

- `/api/diagnostics?reports=1&date=2026-10-16`: manual reports for a UTC date.
- `/api/diagnostics?date=2026-10-16&session=<UUID>`: chunks for that session.
- `/api/diagnostics?key=<URL-encoded object key>`: full JSON.
- Follow the returned `cursor` for more than 100 objects.

Alternatively use Wrangler:

```sh
.local/cloudflare-cli/node_modules/.bin/wrangler r2 object get \
  candc-web-diagnostics/reports/YYYY-MM-DD/REPORT-UUID.json --remote --file /tmp/report.json
```

Compare browser input counts against engine `polled`, `mouseIn/Out`,
`buttonIn/Out`, `keyIn/Out`, and drop counters. An increasing `engineAgeMs` with
browser heartbeats indicates an engine-side stall; advancing engine frames with
no new SDL events points to the browser/SDL handoff. Advancing event counters
with `inputEnabled=false` or persistent capture/grab IDs points to UI routing.
This instrumentation diagnoses the intermittent freeze; it does not claim to
fix it and does not reset input or alter simulation.

Deploy from the repository root using `wrangler.jsonc` and `npm ci`:

```sh
npm test
bash scripts/build.sh
npm run export
.local/cloudflare-cli/node_modules/.bin/wrangler pages deploy release --project-name candc-web --branch main
```
